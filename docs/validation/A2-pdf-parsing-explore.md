## 핵심 발견

### 1. "See Section" 패턴 3회뿐 → Cross-Reference 가정 재검토 필요
261페이지 전체에서 "See Section"이 단 **3회**(대소문자 무시 8회). 섹션 번호 기반 교차참조는 이 매뉴얼에 거의 없고, 실제 교차참조는 **알람코드 ↔ 알람코드** 형태로 관찰:
> 예(p.81): SRVO-094 → "See the description about the PMAL alarm **(SRVO-072)**"

→ 기획이 "See Section X.X" 류 섹션 링크를 전제했다면 이 문서엔 부적합. 교차참조 신호는 `(SRVO-NNN)` 패턴 쪽을 봐야 함(→ 추가 측정 대상, 아래).

### 2. extract_tables() 무효 → 텍스트+정규식 파싱 확정
샘플 p.53·p.81은 구조화된 알람 내용인데 `extract_tables()` 검출 **0**. p.227만 1개(5×6). pdfplumber는 괘선 있는 표만 잡고, 알람 설명은 흐르는 텍스트라 표로 안 잡힌다. → **표 추출 기반 파이프라인은 핵심 데이터를 놓침.** `SRVO-\d{3}` 정규식 + `(Explanation)`/`(Action)` 마커 기반 텍스트 파싱으로 방향 확정.

### 3. SRVO 1코드 = 1청크 구조 유효 (잠정)
p.81에서 `(N) SRVO-NNN <제목>` → `(Explanation)` → `(Action 1/2)` 구조 확인. 알람코드 단위 청킹이 가능해 보임. (49페이지 전체 일관성은 추가 측정으로 확인 - 아래.)

## 미확정 사항 (1차 탐색 시점 기준, 추가 측정 필요)

1. **`(SRVO-NNN)` 역참조 빈도** - 교차참조가 실제로 얼마나 있는지 정량화 필요
2. **`(Explanation)`/`(Action)` 마커 일관성** - 49페이지 중 몇 %에서 일관되게 나오는지

> **후속 측정 (같은 날, 2026-06-05 수행)**: `experiments/a2_pdf_parsing/analyze_srvo_pages.py` 작성·실행, 결과 `result_srvo_analysis.txt`.
> - `(SRVO-NNN)` 괄호 역참조: 49페이지 통틀어 **15회 / 6페이지(12.2%)** 로 희소 → **발견 1 강화**(명시적 교차참조 재료 빈약). 단 SRVO 코드 자체는 223회 언급·고유 105개로 코드 색인 콘텐츠는 풍부.
> - `(Explanation)`/`(Action)` 마커: **~80%** 페이지에서 일관 등장(Explanation 79.6%, Action 81.6%) → **발견 3 잠정 지지**. 단 ~20%는 마커 없음(UI 화면·표·도입부) → 폴백 규칙 필요.
> - 측정 주의: 역참조 패턴은 `\(SRVO-\d{3}\)`(괄호에 코드 단독) 엄격 기준이라 변형 표기는 미포함, 15는 하한값.

## 결론 / 다음 단계

- **A2 "PDF 파싱 가능성"은 긍정적** - 261p 중 49p에 SRVO 알람이 정규식으로 추출 가능한 구조로 존재.
- **"Cross-Reference RAG" 가정은 약함** - 명시적 교차참조(See Section 3 + 괄호역참조 15)가 희소. 명칭·기능을 유지하려면 (a) 암묵적 코드 동시언급 기반으로 재정의하거나 (b) 기획에서 축소하는 것이 정직. → ADR 또는 기획 수정으로 결정 필요.
- **파싱 구현 방향 확정**: 텍스트+정규식. 청킹은 `(Explanation)`/`(Action)` 마커 우선 + 마커 없는 ~20% 페이지 폴백 규칙.
- 본 기록은 1차 탐색(explore) 범위. analyze 단계의 상세 결과 해석은 후속 기록에서 다룬다.
