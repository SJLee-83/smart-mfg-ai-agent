# 프로젝트 규약

문서·코드·커밋에 공통으로 적용하는 규약. 각 ADR 과 검증 문서가 절 번호로 참조.

## 1. 검증되지 않은 가정을 사실로 다루지 않음

- 기획서에 적힌 기술적 주장(정확도 향상, 특정 기법의 효과 등)은 검증 전까지 가설
- "기획서에 그렇게 적혀 있으니 맞다"는 추론 금지
- 미검증 가정 위에 세운 설계는 그 사실을 문서에 명시

## 2. 표기 정직성

문서·주석·커밋 메시지의 구현 범위 표기는 실제와 일치.

- "구현·검증"과 "개념 적용"을 구분해 표기
- 검증 없이 "정확도 X% 향상" 같은 수치 주장 금지. 실제 측정값만 기재
- "Cross-Reference RAG", "Safety Agent" 같은 명칭 부여 시 실제 동작과의 일치 여부 점검
- LangGraph·LangChain 사용과 설계를 구분해 표기
- 배포·스케일·모니터링 등 미수행 항목을 수행한 것으로 표기 금지

표기 근거는 검증·구현 기록(`docs/validation/`, `docs/decisions/`).

## 3. 시크릿·데이터 처리

- LLM API 키와 제조 데이터는 하드코딩 금지. 환경변수로 주입
- `.env` 는 git 제외, `.env.example` 에는 키 이름만 기재(값 없이)
- 제조 도메인 데이터에 민감 정보가 있으면 저장소에 커밋하지 않고 별도 관리
- 공개 저장소이므로 커밋 전 시크릿 노출 점검
