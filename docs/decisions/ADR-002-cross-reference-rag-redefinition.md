# ADR-002: Cross-Reference RAG 기능 재정의 (축소)

- **상태(Status)**: 채택(Accepted)
- **날짜**: 2026-06-05
- **관련**: `docs/validation/A2-pdf-parsing-explore.md`, `docs/mvp-plan.md`(§3.1, §3.2, 기능2, §5.1~5.2, §6-A1), [ADR-001](ADR-001-data-folder-structure.md)

---

## 배경 (Context)

기획서(`docs/mvp-plan.md`)는 **"Cross-Reference RAG"** 를 핵심 차별점으로 내세운다(§3.2). 그 전제는
"답변 내 **`See Section X.X`** 참조 문구를 감지해 해당 섹션을 자동 재검색·병합한다"이며,
Linker Agent(§3.1, §3.2 시나리오 3단계)가 이를 담당한다. 검증 가정 표의 **A1**(§6)도
"Cross-Reference RAG가 참조 문구(`See Section...`)를 안정적으로 감지·재검색한다"로 명시돼 있다.

A2 PDF 파싱 검증(`docs/validation/A2-pdf-parsing-explore.md`)에서 실제 매뉴얼
(`R30iA-Mate-Controller-Maintenance-Manual.pdf`, 261페이지)을 측정한 결과, 이 전제가 실제
구조와 불일치함이 확인됐다:

| 측정 항목 | 값 |
|---|---|
| `See Section` 패턴 (정확 일치, 전체 261페이지) | **3회** |
| 괄호 역참조 `(SRVO-NNN)` | **15회 / 6페이지 (12.2%)** |
| 참고: SRVO 코드 자체 언급 | 223회 / 고유 105개 (코드 색인 콘텐츠는 풍부) |

→ **명시적 교차참조 재료가 희소**하여, 기획서 원안("See Section 감지 → 자동 재검색·병합")은
이 매뉴얼에서 작동할 실질 데이터가 거의 없다. 즉 A1 가정은 **기각**된다.

## 결정 (Decision)

**Cross-Reference RAG 기능을 축소한다.**

- **기존**: `See Section X.X` 감지 → 해당 섹션 자동 재검색·병합 (Linker Agent 주도)
- **변경**: 위 기능 **제거**. 핵심 차별점을 아래 두 가지로 대체한다.
  1. **마커 기반 정교한 청킹** — `(Explanation)`/`(Action)` 마커를 활용, **SRVO 1코드 = 1청크**
  2. **메타데이터 필터링** — `error_code`, `content_type`, `severity` 기반 정밀 검색

### 대체안의 검증 상태 (정직성 메모 — 프로젝트 원칙: 측정한 것만 주장)

대체안 역시 아직 전부 검증된 것은 아니다. 현재까지의 근거를 구분해 기록한다:

- **마커 기반 청킹**: A2 후속 측정에서 `(Explanation)` 79.6%, `(Action)` 81.6%로 **~80% 페이지에서
  일관** 확인 → 1차 청킹 규칙으로 **뒷받침됨**. 단 ~20%(UI 화면·표·도입부)는 마커가 없어 **폴백 규칙
  필요**(미구현).
- **메타데이터 필터링**: `error_code`는 105개 고유 코드가 정규식으로 추출 가능해 **실현 가능**.
  그러나 `content_type`·`severity` 태깅의 정확도는 **아직 미검증** → 별도 검증(A 시리즈) 대상.

## 영향 (Impact)

**기획서(`docs/mvp-plan.md`) 수정 필요 — 구체 위치**
- §3.1 **Linker Agent**: 역할 제거 또는 대폭 축소(메타데이터 필터링 보조로 한정)
- §3.2 **핵심 차별점(Cross-Reference RAG)**: 위 대체안 2가지로 교체
- **기능 2(재귀적 정보 검색 및 교차 참조)**: 제거 또는 "메타데이터 기반 연관 검색"으로 재서술
- §5.1 메타데이터 `ref_section`: 교차참조 자동화 근거가 약하므로 **참고 필드로 강등**(있으면 표기, 자동 추적 안 함)
- §5.2 Enrichment의 "참조 섹션(See Section 3.6) 태깅": **제거**
- §6 검증 가정 **A1**: "기각(See Section 희소)"으로 상태 갱신

**기타 영향**
- **자소서·포트폴리오 어필 포인트 변경**: "See Section 자동 추적 교차참조"를 어필점으로 쓰지 않음.
  대신 "검증으로 가정을 기각하고 기능을 재정의한 의사결정 과정"과 "마커 기반 청킹 + 메타데이터 필터링"을
  정직한 어필점으로 전환.

## 근거 (Rationale)

- 검증 없이 구현했다면 **실제로 작동하지 않는 기능**(See Section 자동 추적)을 핵심 차별점·포트폴리오에
  올릴 뻔했다. A2 검증이 이를 사전에 차단했다.
- "측정된 수치만 주장한다"는 프로젝트 원칙(CLAUDE.md)에 따른 결정. 희소한 재료(3회/15회)를
  "교차참조 기능"으로 포장하는 것은 과장에 해당.
- 기능 축소 자체가 손실이 아니라, **검증 우선 워크플로우가 의도대로 작동한 사례**다.

## 고려한 대안 (Alternatives considered)

1. **원안 유지 (See Section 자동 추적)** — 실데이터 희소로 작동 불가 → **기각**.
2. **암묵적 교차참조로 재정의** — `(SRVO-NNN)` 동시언급/코드 그래프 기반으로 "관련 알람" 연결.
   재료가 아주 없지는 않으나(15회/6페이지) 빈약하고 미검증 → **현재 보류**, 향후 별도 검증 후 재고.
3. **기능 축소 + 마커 청킹·메타데이터 필터링으로 대체** — **채택**. 측정으로 뒷받침되는 방향.
