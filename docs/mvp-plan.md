## 2. 문제 정의 (Problem Definition)

### 2.1 프로젝트 배경 및 대상 선정
- **제조 데이터의 폐쇄성 극복**: 보안상 접근이 어려운 실제 공장 데이터 대신, 글로벌 점유율 1위 FANUC 로봇의 공식 유지보수 매뉴얼을 원천 데이터로 선정하여 현실성·신뢰성 확보
- **타겟 설비**: FANUC R-30iA Mate Controller

### 2.2 제조 현장의 문제점
- **방대한 매뉴얼 검색의 비효율성**: 수백 페이지 매뉴얼에서 에러 코드(SRVO-XXX)를 찾느라 긴급 상황에도 시간 소모
- **숙련도에 따른 대응 편차**: 텍스트 조치 방법만으로는 신입 엔지니어가 실제 부품 위치·교체 순서를 파악하기 어려움
- **다운타임 비용 발생**: 단순 고장도 매뉴얼 숙지 미흡·잘못된 1차 조치로 해결이 지연되어 라인 정지·불필요한 부품 교체 등 추가 비용 발생

### 2.3 해결 필요성
에러 코드만 입력하면 매뉴얼 내 정확한 원인·조치 방법을 즉시 추출하고, 초보자도 따라 할 수 있는 표준 대응 절차(SOP)를 제시하는 AI 시스템 필요

## 3. 제안 솔루션 개요 (Solution Overview)

### 3.1 시스템 전체 구조
- **User Interface**: 작업자가 자연어로 질문 (예: "SRVO-214 퓨즈 에러 해결법 알려줘")
- **Orchestrator Agent**: 사용자 의도 파악 후 하위 에이전트에게 업무 지시
- **Specialist Agent**
  - **Retrieval Agent**: 매뉴얼 Vector DB에서 1차 답변 검색
  - **Safety Agent**: 작업 내용과 연관된 안전 수칙을 최우선 확보

### 3.2 핵심 차별점: 마커 기반 정교한 청킹 및 메타데이터 필터링
- FANUC 매뉴얼의 `(Explanation)`/`(Action)` 마커를 활용해 **SRVO 1코드 = 1청크**로 구조화 청킹하고, `error_code`·`content_type`·`severity` 메타데이터로 정밀 검색한다.
- (A2 검증 결과 기반: 마커 일관성 ~80% 실측 — ADR-002)

### 3.3 에이전트 협업 시나리오 요약
1. **감지**: Orchestrator Agent가 질문에서 에러 코드(SRVO-214) 식별
2. **1차 검색**: Retrieval Agent가 에러 원인·기본 조치 검색
3. **심화 검색**: Retrieval Agent가 `error_code`·`content_type`·`severity` 메타데이터로 관련 청크(상세 증상·조치)를 정밀 검색·확보 (See Section 자동 추적 제외 — ADR-002)
4. **검증**: Safety Agent가 "전원 차단 필수" 안전 수칙 추가
5. **응답**: 작업자에게 원인 + 상세 증상표 + 안전 수칙이 통합된 답변 전달

## 4. 주요 기능 정의 (Key Features)

### 기능 1: 에러 코드 기반 심층 진단 및 솔루션 매핑
- **기능 설명**
  - 사용자가 입력한 자연어(예: "BZAL 알람 떴어")에서 정형화된 에러 코드(SRVO-062) 추출
  - 매뉴얼 '3. TROUBLESHOOTING' 챕터 데이터 기반으로 증상–원인–조치 매핑하여 제시
- **구현 포인트**
  - 단순 텍스트 검색이 아니라, "SRVO-062"의 경우 "배터리 교체"뿐 아니라 "마스터링(Mastering) 필요"라는 후속 조치까지 안내
  - 매뉴얼 본문에서 점검 순서·주의 문구를 함께 추출해 명확한 Step-by-Step 수리 가이드로 변환

### 기능 2: 마커 기반 구조화 청킹
- **기능 설명**
  - `(Explanation)`/`(Action)` 마커로 SRVO 코드 단위 청킹. 마커 없는 ~20% 페이지는 폴백 규칙 적용 (미구현, 검증 필요).
  - (A2 검증 결과 기반 — ADR-002)

### 기능 3: 문맥 기반 안전 규정 자동 경고
- **기능 설명**
  - 제시된 수리 절차에 위험 요소(고전압, 고온 등)가 포함된 경우, 관련 안전 규정(SAFETY PRECAUTIONS)을 찾아 답변 최상단에 WARNING 블록으로 자동 표시
- **구현 포인트 (매뉴얼 근거)**
  - 작업자가 "서보 앰프 교체"를 검색하면, 매뉴얼 "SAFETY PRECAUTIONS" 섹션에서 "전원 차단 후 O분 대기(방전 시간)" 등의 문구를 우선 추출
  - 단순 고장 해결 방법뿐 아니라 사고 예방을 위한 안전 가이드까지 함께 제공

## 5. 데이터 및 기술 활용 계획 (Data & Tech Plan)

### 5.1 데이터 구조화 및 Vector DB 구축 전략
매뉴얼 특성을 반영한 메타데이터 컬럼 설계 적용 (단순 텍스트 청킹이 아니라 PostgreSQL pgvector 기능 극대화 목적)

- **데이터 소스**: R30iA-Mate-Controller-Maintenance-Manual.pdf (FANUC 공식 매뉴얼)

**Vector DB 스키마 설계**

| 컬럼명 | 데이터 타입 | 설명 및 활용 예시 |
|---|---|---|
| id | UUID | 각 데이터 청크의 고유 식별자 |
| embedding | Vector(768) 잠정 — 임베딩 모델 확정 후 변경 가능 (ADR-003) | 임베딩 변환된 벡터값 |
| content | Text | 실제 매뉴얼 텍스트 (예: "SRVO-062 BZAL alarm... Replace battery...") |
| metadata | JSONB | 검색 정확도를 높이는 핵심 필터링 요소 |

metadata(JSONB) Key-Value 예시:
- `error_code`: "SRVO-062" (코드 기반 즉시 검색용)
- `category`: "Troubleshooting" (문제 해결 챕터 한정)
- `ref_section`: "3.4" (향후 확장용 — 현재 미활용, ADR-002 참조)
- `Severity`: "Warning" (안전 경고 여부)

### 5.2 구축 프로세스
1. **PDF Parsing**: "3. TROUBLESHOOTING" 챕터의 테이블 구조를 인식하여 에러 코드 단위로 텍스트 추출
2. **Enrichment**: 추출된 텍스트에 "Action" 단계별 번호를 메타데이터로 태깅 (See Section 태깅 제외 — ADR-002)
3. **Embedding**: Gemini 임베딩(gemini-embedding-001)으로 텍스트를 벡터로 변환하여 PostgreSQL에 저장 (ADR-003)

### 5.3 핵심 기술 스택

| 구분 | 선택 | 역할 | 선정 이유 |
|---|---|---|---|
| LLM | Gemini (구체 모델 A6 검증 후 확정 — ADR-003) | 영문 매뉴얼 내용 이해 + 한국어 실시간 번역·요약 답변 생성 | 추론·다국어 처리 능력으로 전문 용어 훼손 없이 자연스러운 한국어 가이드 제공 |
| Vector DB | PostgreSQL (pgvector) | 대용량 매뉴얼 데이터 벡터 저장·검색 | 관계형 데이터(에러코드·메타데이터)와 비정형 데이터(벡터)를 단일 DB에서 처리, 하이브리드 검색 최적화 |
| Embedding | Google gemini-embedding-001 (출력 768d 잠정 — ADR-003) | 영문 기술 문서 + 한국어 질의 벡터화 | 다국어 임베딩 지원·MRL 차원 선택(768/1536/3072) 가능. 최종 차원은 A9 검증 후 확정 |
| Framework | LangGraph | Multi-Agent 작업 흐름·상태 제어 | 순환형 프로세스(참조 문서 재검색 루프) 구현 + 멀티 에이전트 상태 관리 최적화 |

> 참고: 임베딩 모델·차원은 ADR-003에 따라 **gemini-embedding-001(출력 768d 잠정, MRL)**로 통일. 기존 기획서 내부 불일치(5.1 "Solar" vs 5.3 "OpenAI")는 ADR-003으로 해소. 최종 출력 차원(768/1536/3072)은 부록 A9 검증 후 확정.

## 6. 사용자 시나리오 / 유즈케이스 (User Scenario)

### 6.1 주요 사용자
- **입사 1~3년 차 현장 유지보수 엔지니어**
- 특징: 기본 장비 조작은 가능하나, 수백 개 에러 코드와 복잡한 트러블슈팅 매뉴얼을 전부 숙지하지 못함

### 6.2 사용자 행동 흐름
1. **인지**: 설비 정지 및 알람 확인
2. **질문**: 모바일/태블릿으로 에이전트에게 상황 전송
3. **대기**: 에이전트의 분석 및 가이드 생성
4. **수행**: 제공된 안전 수칙 준수 후 단계별 가이드 수행
5. **완료**: 설비 정상 가동 확인 및 이력 자동 저장

### 6.3 에이전트 간 협업 시나리오 (예: SRVO-062 BZAL 알람)

| 단계 | 담당 | 처리 내용 |
|---|---|---|
| Step 1: 입력 | 사용자 | "로봇에 BZAL 알람이 떴어. 어떻게 해야 해?" |
| Step 2: 진단 | 진단 에이전트 | 발화 분석 → 핵심 키워드 추출 / 식별: Error Code SRVO-062, Symptom BZAL (Battery Zero Alarm) |
| Step 3: 1차 검색 | RAG 에이전트 | 매뉴얼 DB에서 SRVO-062 검색 / 1차 결과: "펄스 코더 배터리 방전. 배터리 교체 필요. 주의: 마스터링 필요." |
| Step 4: 확장 검색 | 연결 에이전트 | "마스터링 필요" 문맥 감지 → 3.4 MASTERING 섹션 자동 재검색(Loop)하여 마스터링 절차 확보 |
| Step 5: 안전 검증 | 안전 에이전트 | 작업 연관 키워드(배터리·전기) 감지 → 안전 수칙 로드 → "전원 상태 확인" 경고 추가 |
| Step 6: 최종 답변 | 가이드 에이전트 | 경고 + 원인 + 조치1(배터리 박스 교체) + 조치2(마스터링 수행, 3.4절 요약 포함) 종합 출력 |

## 7. 기대 효과 및 향후 확장성 (Expected Impact)

### 7.1 기대 효과
- **MTTR(평균 수리 시간) 단축**: 에러 코드 확인 → 매뉴얼 검색 → 조치 파악까지 걸리던 시간을 자연어 질문 1번 + 자동 가이드 응답으로 단축
- **휴먼 에러 감소**: "배터리만 교체하고 마스터링 누락" 같은 초보적 실수 자동 방지 / 안전 규정을 항상 최상단 WARNING으로 노출하여 안전사고 리스크 감소
- **숙련도 편차 완화**: 입사 1~3년 차 엔지니어도 숙련자 수준 대응 절차 지원받아 작업자 간 품질 격차 축소

### 7.2 향후 확장성
- **이미지·멀티모달 확장**: 작업자가 에러 화면·부품 사진·배선 사진을 촬영·업로드하면 Vision AI가 인식해 장비·위치·부품 정보를 RAG 에이전트와 연동하는 멀티모달 수리 도우미로 확장
- **타 장비·타 제조사 수평 확장**: 현재 PoC는 FANUC R-30iA Mate Controller 특화. 동일 구조로 다른 매뉴얼을 Vector DB에 추가하면 설정만 바꿔 여러 설비를 지원하는 범용 "설비 고장 대응 에이전트"로 확장 가능

| A6 | LangGraph 멀티에이전트 구조가 단일 RAG 대비 답변 품질을 높인다 | 멀티에이전트 vs 단순 RAG 비교 (품질·지연·비용) |
| A7 | PostgreSQL pgvector가 이 규모·용도에 적합하다 | 매뉴얼 1종 규모에서 성능·구축 난이도. 대안(Chroma/FAISS) 대비 트레이드오프 |
